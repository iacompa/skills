# Claude

| Target | Build and configuration |

## Build and verify a Claude Code connection

Use the [official quickstart](https://claude.com/docs/connectors/building/quickstart) for a minimal HTTP tool. These examples use a disposable project and a server you control. Run one transport variant per fixture.

```sh
claude mcp add --transport http demo http://localhost:3000/mcp
claude mcp add --transport stdio demo-stdio -- node /absolute/path/to/server.js
claude mcp list
claude mcp get demo
```

- Local scope is the default and applies to your current project. Use `--scope project` for a shared root `.mcp.json` under `mcpServers`, or `--scope user` for personal cross-project use. Inspect an existing entry before editing. The CLI supports environment substitution in documented config fields. Keep real values out of JSON, shell history, and source control. [Scope and environment expansion](https://code.claude.com/docs/en/mcp#mcp-installation-scopes)
- Check server status in `/mcp` and execute one representative read tool from the intended project. Test any intended `@server:protocol://resource/path` reference or MCP prompt in the interactive client. Check elicitation capability and cancellation if you use host-native questions. [Claude Code MCP guide](https://code.claude.com/docs/en/mcp)
- Use `claude mcp login demo` or browser sign-in from `/mcp` for a protected server when authorized. The guide explains preconfigured OAuth, `--callback-port`, and non-browser login. [Claude Code OAuth](https://code.claude.com/docs/en/mcp#authenticate-with-remote-mcp-servers)

For a reusable **Claude Code plugin**, put an optional Code manifest at `.claude-plugin/plugin.json` and the MCP configuration at the plugin root in `.mcp.json` or in the manifest's `mcpServers`. Use `${CLAUDE_PLUGIN_ROOT}` for paths to plugin-owned assets when needed. Test with `claude --plugin-dir ./my-plugin` and check the manifest with `claude plugin validate ./my-plugin`. A team marketplace is a separate catalog at `.claude-plugin/marketplace.json`. Include the manifest, README, and license when building for Anthropic's directory and follow its cross-surface plugin requirements. [Manifest reference](https://code.claude.com/docs/en/plugins-reference) · [Plugin build and test](https://claude.com/docs/plugins/build) · [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces) · [Directory checklist](https://claude.com/docs/plugins/pre-submission-checklist)

## Claude's interactive UI and metadata

- **Widget bridge.** Use the MCP Apps SDK `App` in the sandboxed view. Register `ontoolresult` before `app.connect()`. Read `structuredContent` to render and return ordinary tool content for the conversation. Use `app.callServerTool()` for widget-to-server calls and `app.sendMessage()` for user-initiated widget-to-chat messages. Treat `window.openai` as ChatGPT-specific. [Claude UI quickstart](https://claude.com/docs/connectors/building/mcp-apps/quickstart) · [MCP Apps SDK](https://apps.extensions.modelcontextprotocol.io/api/) · [Send messages](https://claude.com/docs/connectors/building/mcp-apps/send-messages)
- **Tool and resource metadata.** Set `_meta.ui.resourceUri` on the tool to a registered `ui://` resource. Serve it with `text/html;profile=mcp-app`. Use `_meta.ui.csp` on the resource contents for required `connectDomains` and `resourceDomains`. Claude blocks external origins by default and ignores `baseUriDomains`. Use `_meta.ui.visibility` for app-only tool visibility when supported, and `_meta.ui.prefersBorder` for the view border. These fields are MCP metadata. The HTML resource can separately contain ordinary HTML tags. [Claude UI quickstart](https://claude.com/docs/connectors/building/mcp-apps/quickstart) · [Claude design guidelines and Figma UI kit link](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)
- **Layouts.** Fit the design to the reported host context, theme, size, and `safeAreaInsets`. Start with inline. Declare supported modes and handle the actual value returned by `app.requestDisplayMode()`. Claude reports its side panel as `fullscreen` where available. Its resource-level `_meta.ui.preferredDisplayMode` is a Claude extension, so keep the portable view usable with defaults. [Display modes](https://claude.com/docs/connectors/building/mcp-apps/display-modes) · [Design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)
- **Expanded functionality.** App tools, Artifacts entry points, and embedded sites require a remote connector and have eligibility constraints. Claude's documented global entry point consumes `_meta["openai/ui"].entrypoints` containing `{ "type": "global" }` together with `_meta.ui.resourceUri` on a model-visible tool. Use the standard resource mapping even when the host reads this extra key. Embedded sites require `frameDomains` and a compatible site `frame-ancestors` policy. Verify origin approval and organization access. When listed in the directory, entry points and embedded sites require a Verified connector. Keep an inline or text fallback for unavailable modes. [Claude MCP Apps capabilities](https://claude.com/docs/connectors/building/mcp-apps/getting-started) · [Entry points](https://claude.com/docs/connectors/building/mcp-apps/entry-points) · [App tools](https://claude.com/docs/connectors/building/mcp-apps/app-tools) · [Embedded sites](https://claude.com/docs/connectors/building/mcp-apps/embedded-sites)
- **SDK versions.** The Claude MCP Apps quickstart uses a pinned 1.x view SDK and the 1.x TypeScript server package layout. The current 2.x SDK docs show split server and client packages. Match example code to the dependencies in the target repository. [Claude UI quickstart](https://claude.com/docs/connectors/building/mcp-apps/quickstart) · [MCP Apps SDK installation](https://apps.extensions.modelcontextprotocol.io/api/#getting-started)

## OAuth, Auth0, and verification

1. Use OAuth for user data or actions on a remote connector. For public data, assess whether a no-sign-in connector fits. Static credential headers are a limited beta in the Claude-hosted connector setup. For ordinary OAuth discovery, reply with HTTP `401` and a `WWW-Authenticate: Bearer` challenge that points at the protected-resource metadata. Match the metadata's `resource` to the exact endpoint URL including its path. Serve reachable authorization-server discovery, support S256 PKCE, and exercise token refresh. [Authentication for connectors](https://claude.com/docs/connectors/building/authentication) · [MCP authorization tutorial](https://modelcontextprotocol.io/docs/tutorials/security/authorization)
2. Choose client registration and callbacks for each client. For hosted Claude, register `https://claude.ai/api/mcp/auth_callback`. Claude Code uses a loopback callback with an ephemeral port by default. For pre-registration, see `--callback-port` and the Code version note. Hosted Claude normally selects CIMD when discovery advertises `client_id_metadata_document_supported: true` and `none` in `token_endpoint_auth_methods_supported`. Verify the documented DCR, confidential client, or pre-registered credential alternatives against the target connector. [Claude client registration and redirects](https://claude.com/docs/connectors/building/authentication#register-claude-as-an-oauth-client) · [Claude Code OAuth](https://code.claude.com/docs/en/mcp#authenticate-with-remote-mcp-servers)
3. With Auth0 as the authorization server, follow its MCP resource setup, configure its resource-parameter compatibility as required, and register or enable the exact client mechanism needed by your tenant. Auth0 documents manual CIMD, tenant-dependent dynamic CIMD, and DCR separately. Keep Auth0's own tenant-management MCP server separate from securing a server you build. [Auth0 MCP authorization quickstart](https://auth0.com/ai/docs/mcp/get-started/authorization-for-your-mcp-server) · [MCP client registration](https://auth0.com/ai/docs/mcp/guides/registering-your-mcp-client-application) · [Resource parameter configuration](https://auth0.com/ai/docs/mcp/guides/resource-param-compatibility-profile) · [Auth0 Auth for MCP](https://auth0.com/ai/docs/mcp/overview)
4. For a mixed public and private tool set, see Claude's lazy sign-in flow. The protected call triggers a real HTTP `401` before the MCP SDK processes it. For enterprise auto-connect, use Anthropic's identity-assertion flow where eligible and still validate the assertion and enforce permissions. [Lazy authentication](https://claude.com/docs/connectors/building/lazy-authentication) · [Enterprise Managed Auth](https://claude.com/docs/connectors/building/enterprise-managed-auth)

## Test and distribute

- **Protocol first.** Use a reviewed Inspector version to connect, list tools, validate input and output, and read the UI resource if there is one. Use the [local Inspector commands](mcp-core.md#inspect-the-protocol-and-then-exercise-the-host). Test sign-in, least-privilege scope, token expiry and refresh, and actionable errors with fixtures. Use `clientInfo` only for diagnostics and use negotiated capabilities and client evidence for behavior. [Claude testing guide](https://claude.com/docs/connectors/building/testing) · [Auth0 Inspector guide](https://auth0.com/ai/docs/mcp/guides/test-your-mcp-server-with-mcp-inspector)
- **Host second.** With authorization, use an HTTPS endpoint and add it in Claude under Customize → Connectors → Add custom connector. For a local server in the hosted Claude path, expose only a dedicated test endpoint through an authorized tunnel, with authentication when the fixture uses protected data. Test the actual connector in Claude for permissions, rendering, and mobile or display-mode behavior. Test Code independently through `/mcp`. [Test in Claude](https://claude.com/docs/connectors/building/testing) · [MCP Apps troubleshooting](https://claude.com/docs/connectors/building/mcp-apps/troubleshooting)
- **Connectors Directory.** For public listing, check tool review criteria and the submission requirements for your connector or app. Separate read and write tools. Use accurate titles and the applicable `readOnlyHint` or `destructiveHint` from the review rules. Prepare docs, a privacy policy, support contact, and an icon. For an MCP App, the current guide asks for three to five PNG screenshots at least 1,000 pixels wide, with paired prompts supplied separately. The directory portal has distinct submission types for a plugin bundle and a remote MCP connector. A local `.mcpb` is for direct Desktop distribution. The current connector submission guide routes a local server intended for the directory through a plugin. [Connector review](https://claude.com/docs/connectors/building/review-criteria) · [Connector submission](https://claude.com/docs/connectors/building/submission) · [Directory publication](https://claude.com/docs/directory/publish) · [Plugin submission](https://claude.com/docs/plugins/submit)
